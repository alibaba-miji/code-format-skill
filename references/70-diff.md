# 70 · diff、提交与变更说明（R-DIF）

> 准备提交、整理分支、处理合并冲突或写变更说明时，按实际交付方式选用。

## R-DIF-01 让功能差异与格式变更容易区分

- **内容**：核对每个文件和每片差异与本次目的的关系。大量格式变化、自动生成内容或重排掩盖行为修改时，按项目约定隔离或缩小它们，让 reviewer 能看到实际改变的逻辑。
- **为什么**：一段逻辑和几百行无关的对齐变化混在一起，会增加漏审行为变化和误回退无关工作的机会。
- **坏例**：
```text
commit 1: 格式化 12 个旧文件（无语义变化）
commit 2: 同一特性的另一半实现
commit 3: 同一特性的测试
# 外加 18 处纯折行/对齐；diff 里 72% 行数是测试重排
+shape.tiles                           = ...     # 仅对齐，26 个空格
```
- **好例**：
```text
单个 commit：实现 + 测试 + BUILD，仅含语义改动
核对格式变化后，最终 diff 仅含与本次功能相关的修改。
格式化检查：clang-format --lines=<改动行>
```
- **判定**：能否定位本次行为变化及其必要依赖。忽略空白等比较方式只用于辅助定位，还要按语言语法核对缩进和字符串等有意义的变化。
- **例外**：统一格式或更新受版本控制的生成产物本身就是任务时，按相应规则验证结果。

## R-DIF-02 按实际审查和集成方式检查提交边界

- **内容**：整理提交时，确认项目是逐个提交集成，还是只集成整个变更。需要独立审查、验证或回退的单元，应带齐它依赖的实现与测试。修订被他人审过的代码时，保留足以看清增量的比较依据。
- **为什么**：一个提交若依赖后续才加入的构建目标，单独检出就会失败。改写已共享的历史还可能让审查依据或他人的提交丢失。
- **坏例**：
```text
# WIP 阶段
a1b2c3d feat: eplb 监控（第一版）
d4e5f6a fix: 补前一提交遗漏的直接依赖   # 本次要求每个功能提交均能独立构建

# review 阶段
把历史改写后只给 reviewer 新提交，丢掉上轮对照依据
```
- **好例**：
```text
# 本次按完整功能整理 WIP
a1b2c3d feat: 固定 GPU 窗口统计与 token 加权上报

# 用户要求单独审查本轮修改，故保留修复提交
e7f8a9b fix: 按 review 意见删除每步 zero_ 并补 wave 计数断言
```
- **判定**：按实际集成单位检出代码后，其直接依赖是否齐全。评审者能否比较上次审过的内容与本次修复。操作共享历史是否符合当前授权和协作约定。
- **例外**：允许合并时压缩整个变更的工作流，可按最终合入单元核对完整性。

## R-DIF-03 变更说明提供与行为主张相称的依据

- **内容**：让读者能判断改了什么、谁会受到影响、依据是什么。指标口径变化时解释定义与边界，性能结论给测量条件，能力在不同环境下有差异时写清覆盖范围。按本次变更实际涉及的内容组织。
- **为什么**：“支持所有后端”或“性能提升”会影响使用决策。若证据只涵盖部分配置或测量场景，读者会高估覆盖面。
- **坏例**：
```text
EPLB 变更说明只有“重构指标汇报，测试通过”。读者看不出无计数后端会得到什么结果。
```
- **好例**：
```text
这次 EPLB 变更同时改了指标口径、汇报时机和支持范围。
说明按步骤和层聚合负载，并交代该版本约定的空窗口值。
列出实际测过的 eager 与 graph 场景，以及各自能观察到哪些阶段。
DeepEP 和 DeepGEMM Mega 有计数来源，dense / EP=1 没有相同的计数数据。
```
- **判定**：读者依据说明做决定时，是否会把推测当实测、把局部支持当成通用能力，或忽略行为变化。

## R-DIF-04 核对合并冲突解决后的行为变化

- **内容**：解决合并冲突时，比较双方意图与合并结果。如果合并需要改变行为，说明取舍以及受影响的调用者，使 reviewer 能定位这部分新增判断。
- **为什么**：两边分别通过的代码拼到一起，也可能丢掉一方的行为。只说明“冲突已解决”看不出这类回归。
- **坏例**：
```text
回报：「已 rebase 最新 main 并解决冲突，UT 全绿」
实际：解冲突时改写了命名、调整了错误码、顺手简化了一个分支
```
- **好例**：
```text
A.cc 保留原 CRC 判定。B.cc 接入主线的新签名。
C.h 的新签名改变了错误码的传递方式，列出受影响的调用方，并核对它对错误码的处理。
```
- **判定**：能否看出冲突双方的重要行为在最终结果中如何体现，是否引入需要重审的语义变化。
- **例外**：两种产品行为确实互斥且现有契约无法裁决时，明确提出有待决定的具体取舍。
